## 0. Why this document exists

Strategy A must not be defined by whatever the current code happens to do.

This document separates four different things that are easy to accidentally mix:

1. **Source meaning** — what the original strategy teaching says.
2. **Codified meaning** — the deterministic rule we can actually write down.
3. **Implementation** — what the current Strategy A code really does.
4. **Research evidence** — what the historical tests have and have not validated.

A disagreement between these layers is a finding, not something to silently resolve by assumption.

### Non-negotiable rule

If the source does not provide enough information to define a numeric rule safely, the rule remains **UNKNOWN / TBD**. We do not invent thresholds, formulas, tolerances, or exceptions merely to make the code convenient.

# 2. Core philosophy extracted from the source

## 2.1 Strategy is a complete plan, not an entry pattern

The source explicitly frames a strategy as a plan that is known **before** the market action unfolds. It includes why to enter, when to enter, what time of day to trade, what timeframe to use, where to exit, and what to do if price moves against the expected direction.

Therefore Strategy A is not canonically equivalent to:

> “When candle X breaks level Y, buy/sell, put the stop here, and target the same distance.”

That is only one possible component of a strategy.

**Canonical implication:** entry, invalidation, exit, timing/session, timeframe, and reaction-to-adverse-move rules must be treated as one coherent system.

Source evidence: approximately 3:44–4:56 in the raw transcript.

---

## 2.2 Repeatability is fundamental

The source emphasizes that the same recognizable situation must produce the same predefined response. If situation `X` occurs today and the trader takes action `2`, then a materially equivalent `X` tomorrow must receive the same action `2`.

Changing the reaction because the chart “feels different” creates a different trade/action and invalidates statistical aggregation of the two cases.

**Canonical rule:** a setup definition must be sufficiently precise that equivalent occurrences can be classified consistently without discretionary reinterpretation.

Source evidence: approximately 6:10–8:48.

---

## 2.3 Strategy means fixed behavior against variable outcomes

The source distinguishes the deterministic behavior from the stochastic result. The same action can produce profit on one occurrence and loss on another. That does not mean the action itself should be changed after the fact.

**Canonical implication:** backtesting measures the distribution of outcomes generated by a fixed rule; it is not permission to change the rule trade-by-trade.

Source evidence: approximately 8:39–9:58.

---

## 2.4 Risk/reward is a numbers game, not an emotional game

The source emphasizes the distribution of risk versus gain rather than requiring a high percentage of winning trades. Once the system specifies a numerical exit, changing it emotionally damages the system being tested.

**Canonical implication:** SL/TP/exit rules must be deterministic in the backtest. Manual exceptions cannot be mixed into the same performance population unless explicitly modeled as a separate strategy.

Source evidence: approximately 10:22–12:41.

---

## 2.5 Candles must be read as sequential information

The source describes price action as a language in which candles are words. Even on low timeframes, each candle contributes information through its open, high, low, and close and through its relationship to preceding candles.

The source specifically discusses M1, M5, and M15 and emphasizes examining candle-by-candle behavior rather than treating the chart only as a smooth wave.

**Canonical implication:** any machine implementation that uses candle structure must define which OHLC relationships are causal and which future information is forbidden.

Source evidence: approximately 18:27–21:04.

---

## 2.6 Structure and repeated behavior matter more than visual storytelling

The source gives examples involving successive highs/lows, breakout behavior, gaps/displacement-like movement, extension of candles, and repeated directional structure.

**Canonical implication:** visual labels such as “strong move” or “nice structure” are not sufficient implementation rules. They must eventually become measurable conditions.

Source evidence: approximately 19:34–21:50.

# 4. SP2L semantic nucleus

## 4.1 Name

Working expansion:

**SP2L = Spike → 2 Legs / SPIKE-2LEG**

This is treated as a semantic concept from the supplied strategy source and project research. It must not be confused with any later experimental shortcut unless the exact relationship is documented.

## 4.2 Working conceptual model

The current project understanding is:

1. A **Spike** is a sufficiently sharp directional move occurring after a relevant range/context.
2. The move establishes **Leg 1**.
3. A correction/pullback occurs.
4. A projected **Leg 2** is expected to develop, with the relationship between legs being part of the setup logic.
5. Entry occurs only after the required trigger conditions are satisfied.
6. Stop and target are defined as part of the setup, not improvised after entry.

This paragraph is a **working model**, not yet a claim that every numeric detail has been extracted from the source.

## 4.3 Numeric rules still requiring canonical extraction

The following must not be guessed:

- minimum/maximum Spike size;
- reference range definition;
- Spike duration / candle-count constraints;
- whether Spike is measured in absolute price, points, ATR, or another normalized unit;
- exact Leg 1 start and end;
- exact correction boundaries;
- minimum/maximum correction depth;
- exact Leg 2 projection formula;
- what makes a 2L “valid”;
- exact Trigger definition;
- whether entry is at close, limit, stop, retest, or another event;
- exact SL placement;
- exact TP1 / TP2 placement;
- handling of spread/slippage;
- invalidation conditions;
- multi-entry / 2X behavior;
- position aggregation rules;
- session restrictions;
- timeframe-specific differences.

Until these are resolved, code must not silently choose values and call them “Poorsamadi rules.”

# 7. Research status — what has actually been learned

## 7.1 Post-entry T1 information

Recent research tested whether first post-entry MAE carries information about canonical final R.

Conditional-information results showed robust information in **T1** across M1/M5 and DEV/VAL, while T2 conditional on T1 and T3 conditional on T1/T2 did not show robust incremental information.

This is evidence about the **implemented baseline's outcome path**, not proof that T1 is part of the original strategy.

## 7.2 T1 extreme state

The fresh-holdout study found a strong 5-minute replication: the highest T1-MAE state was economically worse than lower states across 3/4/5 bins, with fresh effects remaining negative and confidence intervals below zero.

However, the subsequent state-transition analysis showed that on M5 the extreme state is almost always already the canonical stop-loss event on the first post-entry candle. Therefore it is **not currently an independent actionable early-exit state transition**.

## 7.3 Economic filtering

Filtering the highest T1-MAE state produced a strong M5 fresh-holdout economic improvement in the research experiment, especially with 3 bins.

But T1 is only known **after entry**. Therefore this is a post-entry management/filtering result, not a pre-entry entry filter.

No production rule has been promoted from this result.

## 7.4 Early exit

Early-exit experiments did not demonstrate stable economic improvement across validation/fresh holdout. This hypothesis is rejected for promotion at the current stage.

# 8. Research guardrails

These rules govern all future work derived from this map.

1. **No production rule from exploratory evidence alone.**
2. DEV may be used to formulate/freeze a hypothesis; VAL is chronological OOS validation.
3. Fresh holdout remains protected until explicit replication is justified.
4. Thresholds must not be optimized against VAL or fresh holdout.
5. Candidate reconstruction must match the canonical Strategy A baseline exactly.
6. No hindsight leakage.
7. Same-candle ambiguity is handled conservatively.
8. A statistically significant association is not automatically an economically useful trading rule.
9. A post-entry feature cannot be relabeled as a pre-entry feature.
10. A rule derived from an experiment must be explicitly separated from the original semantic strategy.
11. If the source and code disagree, document the disagreement before changing either one.
12. Preserve research artifacts; do not delete historical reports merely because a hypothesis was rejected.

**Answer:** Not yet proven.

## Q2 — Are the current numeric Spike/Leg/Trigger definitions the teacher's intended numeric definitions?

**Answer:** Not yet established.

Current numeric rules are implementation facts unless explicitly tied to a source statement.

## Q3 — Are M1 and M5 intended to be identical rule sets?

**Answer:** Unknown.

The source discusses both low timeframes, but timeframe-specific codification must be established explicitly.

## Q4 — Are multi-entry / 2X trades part of the same statistical unit as a single baseline trade?

**Answer:** No assumption is allowed.

They must be modeled explicitly and kept separate until the source and deterministic rules establish how they relate.

## Q5 — Does a post-entry T1 state belong to the original entry strategy?

**Answer:** No, not by timing.

It is an observed post-entry state. It may support a separate management rule only after independent validation.
