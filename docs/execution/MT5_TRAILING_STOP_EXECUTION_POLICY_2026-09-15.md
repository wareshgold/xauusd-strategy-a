# MT5 Trailing Stop — Execution Policy

**Status:** RESEARCH / EXECUTION-LAYER ONLY  
**Date:** 2026-09-15  
**Strategy geometry:** UNCHANGED  
**Production activation:** OFF

## Purpose

Record the requested MT5-native trailing-stop capability without changing or inventing SP2L Strategy A source geometry.

## Boundary

Trailing Stop is treated as an execution/position-management feature for the MT5 runtime. It is not a source-derived SP2L entry, breakout, correction, AB=CD, invalidation, target, or trigger rule.

## Current policy

- Capability: planned.
- Default state: **OFF**.
- No trailing-stop logic is enabled in the current Strategy A research baseline.
- No historical/backtest result may include trailing-stop effects unless a separate, pre-registered experiment explicitly enables it.
- No production BUY/SELL decision is generated by this document.

## Parameters intentionally unresolved

The project must not invent the following values or semantics:

1. trailing distance;
2. activation threshold;
3. step/increment, if any;
4. whether movement is tick-based or bar-based for research simulation;
5. handling around spread, stops level, freeze level, or broker constraints;
6. whether a trailing stop may move only in the favorable direction (runtime expectation) and the exact implementation contract;
7. whether the same behavior must be simulated identically in the research engine and MT5 runtime.

These are execution specifications, not Strategy A source geometry. They require an explicit engineering decision before implementation and a deterministic specification before statistical evaluation.

## Separation from existing experiment

The current fixed working hypothesis remains independent:

- initial SL: 50/60/70/80 pips as separate test values;
- target: 2.0R;
- no trailing stop in baseline outcomes.

If trailing stop is evaluated later, it must be reported as a separate treatment and must not replace the no-trailing baseline.

## Acceptance gate for future implementation

Before enabling this feature:

1. freeze the MT5 execution parameters in a written contract;
2. implement deterministic unit tests for monotonic SL movement and broker-distance constraints;
3. verify behavior in MT5 Strategy Tester/runtime;
4. keep trailing-stop-on results separate from the baseline;
5. do not infer source geometry from improved performance.

**Conclusion:** MT5 trailing stop is now explicitly tracked as an optional execution-layer capability, but remains OFF and non-canonical until separately specified and validated.
